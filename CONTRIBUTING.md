# Contributing

Thanks for taking an interest in this project.

## Development workflow

1. Create a focused branch from `main`.
2. Make one logical change at a time.
3. Test the change locally before opening a pull request.
4. Update the README or documentation when behavior changes.
5. Open a pull request with a clear summary and testing notes.

## Commit messages

Use the Conventional Commits style:

```text
<type>: <short imperative description>
```

Common types include:

- `feat`: add user-facing functionality
- `fix`: correct a bug
- `docs`: improve documentation
- `refactor`: restructure code without changing behavior
- `test`: add or update tests
- `chore`: maintain tooling or configuration

Keep the subject concise, use the imperative mood, and explain important context in the body when needed.

Examples:

```text
feat: add keepsake filtering
fix: handle empty memory collections
docs: clarify local setup
```

## Pull requests

Please include:

- What changed and why
- How the change was tested
- Screenshots or a short recording for visual changes
- Any follow-up work or known limitations
